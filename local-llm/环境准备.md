# 模型下载失败（WinError 10054 / 连接被关闭）

国内访问 Hugging Face 常出现「远程主机强迫关闭了一个现有的连接」。可用以下方式解决：

1. **脚本已内置国内镜像**：`download_model.py` 会自动使用 `HF_ENDPOINT=https://hf-mirror.com`，并带重试，直接再运行一次即可：
   ```bash
   python .\local-llm\download_model.py --model deepseek-vl
   ```

2. **手动指定镜像（可选）**：若仍失败，可在运行前设置环境变量：
   - PowerShell：`$env:HF_ENDPOINT = "https://hf-mirror.com"`
   - CMD：`set HF_ENDPOINT=https://hf-mirror.com`
   然后再执行上述 Python 命令。

3. **使用代理**：如有稳定代理，可先设置 `HTTP_PROXY`/`HTTPS_PROXY`，再运行下载脚本。

## PointLLM：`Tensor.item() cannot be called on meta tensors`

使用 `ply_point_tagger.py` 加载 PointLLM 时，若报错栈指向 **`PointLLM\pointllm\model\pointbert\point_encoder.py`** 中 `torch.linspace(...).item()`，原因如下：

- `transformers` 的 `from_pretrained(..., low_cpu_mem_usage=True)` 会在 **meta 设备** 上先搭建模型骨架；
- 该模式下 `torch.linspace` 得到的是 **meta 张量**，对其调用 `.item()` 会触发上述错误（CPU / GPU 均可能出现，取决于加载参数）。

**推荐修复（一次修改，长期有效）**：在 `PointLLM\pointllm\model\pointbert\point_encoder.py`（与克隆或 `pip install -e .` 的根目录一致）中，不要用 `linspace` + `.item()`，改为与 `torch.linspace(0, drop_path_rate, depth)` **等价的 Python float 列表**（等间距从 0 到 `drop_path_rate`，共 `depth` 个点，用于 Stochastic Depth 的逐层率 `dpr`）。将原先：

```python
dpr = [x.item() for x in torch.linspace(0, self.drop_path_rate, self.depth)]
```

替换为：

```python
# Use Python floats so init works under HF meta-device (low_cpu_mem_usage) —
# torch.linspace there yields meta tensors and .item() is invalid.
depth, rate = self.depth, float(self.drop_path_rate)
if depth <= 1:
    dpr = [rate]
else:
    dpr = [rate * i / (depth - 1) for i in range(depth)]
self.blocks = TransformerEncoder(
    embed_dim=self.trans_dim,
    depth=self.depth,
    drop_path_rate=dpr,
    num_heads=self.num_heads
)
```

（若你本地的 `TransformerEncoder(...)` 参数与上表不完全一致，只替换 `dpr` 的构造方式即可，下一行仍接你文件里原有的 `self.blocks = TransformerEncoder(...)`。）

**备选**：若仅本地脚本可控、不便改 PointLLM 仓库，可在加载逻辑里对 PointLLM 关闭 `low_cpu_mem_usage`（内存占用会升高）。本仓库的 `ply_point_tagger.py` 在 **CPU** 上已设置 `device_map=None`，若仍遇此问题，优先确认实际参与加载的 `PointLLM` 包是否已包含上述 `point_encoder.py` 修补。

# 视频抽帧 + 图像打标（video_extract_frames_tagger.py）

用 **OpenCV 按间隔抽帧**，再对每一帧调用与 `image_tagger.py` 相同的 **DeepSeek-VL / BLIP-2** 流程打标，最后聚合为视频级 JSON。不依赖 Qwen2.5-VL，模型路径与 `image_tagger.py` 一致。

在项目根目录（如 `D:\ai\myidea`）下执行。**`--video` 必填**。

## 基本用法（本地 DeepSeek-VL）

```bash
python .\local-llm\video_extract_frames_tagger.py --video .\video-tag-file\运动2.mp4 --model_path .\deepseek_vl_chat_model\
```

## 默认输出位置（不写 `--output` / `--frames_dir`）

与 **视频文件同级目录**，按 **视频主文件名** 与 **模型名后缀**（规则同 `image_tagger`：本地模型取目录名，`--model_path` 不传时为 `default`）命名：

- 汇总 JSON：`{视频主文件名}_{模型名}.json`
- 抽帧目录：`{视频主文件名}_{模型名}_extracted_frames`

例如视频为 `.\video-tag-file\运动2.mp4`、模型目录为 `deepseek_vl_model`，则默认为 `video-tag-file\运动2_deepseek_vl_model.json` 与 `video-tag-file\运动2_deepseek_vl_model_extracted_frames\`。

## 手动指定输出与抽帧目录

```bash
python .\local-llm\video_extract_frames_tagger.py --video .\你的视频.mp4 --model_path .\deepseek_vl_model\ --output my_video_frames.json --frames_dir .\my_frames\
```

## 调整抽帧密度与上限

- `--frame_interval`：每隔多少帧采一帧（默认 `10`）
- `--max_frames`：最多分析多少帧（默认 `100`）

```bash
python .\local-llm\video_extract_frames_tagger.py --video .\你的视频.mp4 --model_path .\deepseek_vl_model\ --frame_interval 30 --max_frames 50
```

## 与 image_tagger 一致的模型与设备参数

```bash
python .\local-llm\video_extract_frames_tagger.py --video .\你的视频.mp4 --model_path .\deepseek_vl_model\ --device cuda --max_tokens 512
```

```bash

```
