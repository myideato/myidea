# 四台 GPU 物理机分布式图像打标实施方案

---

## 一、方案概览

| 方案 | 架构 | 适用场景 | 复杂度 |
|------|------|----------|--------|
| **方案 A** | 本地加载 + 数据并行 | 批量打标、追求最高吞吐 | ⭐ 低 |
| **方案 B** | 集中式 API 部署 | 多用户、动态负载、统一入口 | ⭐⭐⭐ 高 |

---

## 二、环境假设

- **机器数量**：4 台 GPU 物理机
- **机器标识**：`gpu-node-01` ~ `gpu-node-04`
- **共享存储**：数据集目录 `/data/images/` 可被 4 台机器访问（NFS 或本地复制）
- **模型**：DeepSeek-VL 7B（约 24GB 显存）或 BLIP2（约 7～14GB）
- **工具**：`image_tagger.py`、`download_model.py`

---

### 3.2 实施步骤

#### 步骤 1：准备模型（每台机器执行一次）

```bash
# 在每台机器上执行，或从一台复制到其他机器
cd /path/to/local-llm
python download_model.py --model deepseek-vl --output_dir ./deepseek_vl_model
```

#### 步骤 2：数据分片

将数据集按 4 份切分，每台机器处理 1/4：

```python
# split_dataset.py
import os
import shutil
from pathlib import Path

def split_dataset(src_dir: str, num_parts: int = 4, output_base: str = "/data/parts"):
    """将数据集按文件列表均分到 num_parts 个子目录"""
    exts = {'.jpg', '.jpeg', '.png', '.bmp', '.gif', '.webp'}
    files = []
    for root, _, fnames in os.walk(src_dir):
        for f in fnames:
            if Path(f).suffix.lower() in exts:
                files.append(os.path.join(root, f))
    
    files.sort()
    part_size = (len(files) + num_parts - 1) // num_parts
    
    for i in range(num_parts):
        part_dir = os.path.join(output_base, f"part_{i}")
        os.makedirs(part_dir, exist_ok=True)
        chunk = files[i * part_size : (i + 1) * part_size]
        for f in chunk:
            # 软链接或复制
            dst = os.path.join(part_dir, os.path.basename(f))
            if not os.path.exists(dst):
                os.symlink(os.path.abspath(f), dst)  # 或 shutil.copy2(f, dst)
    
    print(f"已分片: {len(files)} 张图 → part_0~{num_parts-1}")

# 使用: split_dataset("/data/images", 4)
```

或使用简单 shell 分片（按文件名哈希）：

```bash
# 假设图片在 /data/images 下
for i in 0 1 2 3; do mkdir -p /data/parts/part_$i; done
cd /data/images
n=0
for f in $(find . -type f \( -iname "*.jpg" -o -iname "*.png" -o -iname "*.jpeg" \)); do
  dest=$((n % 4))
  ln -sf "$(realpath $f)" "/data/parts/part_$dest/$(basename $f)"
  ((n++))
done
```

#### 步骤 3：各机器并行执行

在 **gpu-node-01** 上：

```bash
python image_tagger.py --model_path ./deepseek_vl_model --batch_dir /data/parts/part_0 \
  --output /data/results/results_0.json --save_sibling
```

在 **gpu-node-02** 上：

```bash
python image_tagger.py --model_path ./deepseek_vl_model --batch_dir /data/parts/part_1 \
  --output /data/results/results_1.json --save_sibling
```

在 **gpu-node-03**、**gpu-node-04** 上同理，分别使用 `part_2`、`part_3` 和 `results_2.json`、`results_3.json`。

#### 步骤 4：结果汇总

```python
# merge_results.py
import json
import glob

def merge_results(pattern: str = "/data/results/results_*.json", out: str = "/data/results/tags_all.json"):
    all_results = []
    for path in sorted(glob.glob(pattern)):
        with open(path, 'r', encoding='utf-8') as f:
            all_results.extend(json.load(f))
    with open(out, 'w', encoding='utf-8') as f:
        json.dump(all_results, f, ensure_ascii=False, indent=2)
    print(f"合并完成: {len(all_results)} 条 → {out}")
```

### 3.3 一键启动脚本（需 SSH 免密）

```bash
# run_distributed.sh
NODES=("gpu-node-01" "gpu-node-02" "gpu-node-03" "gpu-node-04")
WORK_DIR="/path/to/local-llm"
MODEL_PATH="$WORK_DIR/deepseek_vl_model"

for i in "${!NODES[@]}"; do
  node="${NODES[$i]}"
  ssh "$node" "cd $WORK_DIR && python image_tagger.py --model_path $MODEL_PATH \
    --batch_dir /data/parts/part_$i --output /data/results/results_$i.json --save_sibling" &
done
wait
echo "所有节点完成，请执行 merge_results.py 汇总"
```

## 四、方案 B：集中式 API 部署

### 4.1 架构示意

```
                    ┌───────────────────────────────────────┐
                    │  客户端（任意机器，可无 GPU）           │
                    │  读取多模态文件 → 请求负载均衡 → 汇总    │
                    └─────────────────┬─────────────────────┘
                                      │
                    ┌─────────────────┴─────────────────┐
                    │      负载均衡 / 请求分发            │
                    │    (Nginx / 自研调度器)            │
                    └─────────────────┬─────────────────┘
                                      │
            ┌────────────────┬────────────────┼────────────────┬
            ▼                ▼                ▼                ▼
        ┌─────────┐     ┌─────────┐       ┌─────────┐      ┌─────────┐
        │gpu-01   │     │gpu-02   │       │gpu-03   │      │gpu-04   │
        │API:8000 │     │API:8000 │       │API:8000 │      │API:8000 │
        │模型+推理 │     │模型+推理│       │模型+推理 │      │模型+推理 │
        └─────────┘     └─────────┘       └─────────┘      └─────────┘
```

### 4.2 实施步骤

#### 步骤 1：在 4 台 GPU 机器上部署 API

- 4 台机器均跑模型 API（如 8000 端口），全部参与推理
- 客户端可跑在任意机器（含无 GPU 的调度机，或任选一台 GPU 机）

#### 步骤 2：Nginx 负载均衡配置

```nginx
upstream vl_api {
    server gpu-node-01:8000;
    server gpu-node-02:8000;
    server gpu-node-03:8000;
    server gpu-node-04:8000;
}

server {
    listen 9000;
    location / {
        proxy_pass http://vl_api;
        client_max_body_size 50M;
    }
}
```

#### 步骤 3：客户端批量请求

```python
# api_client.py
import requests
import os
import json
from pathlib import Path
from concurrent.futures import ThreadPoolExecutor, as_completed

API_BASE = "http://gpu-node-01:9000"  # 或负载均衡地址
DATASET_DIR = "/data/images"
OUTPUT_FILE = "/data/results/tags_all.json"
MAX_WORKERS = 8

def tag_one(path: str) -> dict:
    with open(path, 'rb') as f:
        r = requests.post(f"{API_BASE}/tag", files={"image": f}, timeout=60)
    return {**r.json(), "image_path": path}

def main():
    exts = {'.jpg', '.jpeg', '.png', '.bmp', '.gif', '.webp'}
    files = []
    for root, _, fnames in os.walk(DATASET_DIR):
        for f in fnames:
            if Path(f).suffix.lower() in exts:
                files.append(os.path.join(root, f))
    
    results = []
    with ThreadPoolExecutor(max_workers=MAX_WORKERS) as ex:
        futures = {ex.submit(tag_one, p): p for p in files}
        for fut in as_completed(futures):
            try:
                results.append(fut.result())
            except Exception as e:
                results.append({"image_path": futures[fut], "error": str(e)})
    
    with open(OUTPUT_FILE, 'w', encoding='utf-8') as f:
        json.dump(results, f, ensure_ascii=False, indent=2)

if __name__ == "__main__":
    main()
```

### 4.3 方案 B 特点

- 单入口，便于多用户、多客户端使用
- 图片需经网络上传，存在带宽与延迟开销
- 适合实时、零散请求；大批量打标时吞吐通常低于方案 A

---

## 五、方案对比与选型

| 维度 | 方案 A 本地并行 | 方案 B 集中式 API |
|------|-----------------|-------------------|
| **吞吐量** | 最高 | 受网络与调度影响 |
| **实现复杂度** | 低 | 高 |
| **数据流** | 本地读图 | 上传图片到 API |
| **扩展性** | 加机器需改分片 | 负载均衡自动扩展 |
| **多用户/实时** | 不适合 | 最适合 |
| **故障隔离** | 单机故障影响 1/4 | 单点故障影响大 |

### 选型建议

| 需求 | 推荐方案 |
|------|----------|
| 已知数据集、批量打标、追求吞吐 | **方案 A** |
| 多团队、多用户、统一入口 | **方案 B** |

## 六、附录

### A. 模型与显存参考

| 模型 | 显存需求 | 推荐场景 |
|------|----------|----------|
| DeepSeek-VL 7B | ~24GB | 高质量结构化打标 |
| Qwen2.5-VL 7B | ~12GB+ | 中文友好、结构化 |
| BLIP2 | 7～14GB | 轻量、简单描述 |

### B. 相关文件

- `image_tagger.py`：核心打标逻辑
- `download_model.py`：模型下载
- `开源视觉语言模型推荐.md`：模型选型参考

### C. 注意事项

1. **数据分片**：优先按文件数均分，避免按目录分导致单机数据量差异大。
2. **断点续跑**：可在 `image_tagger.py` 中增加「跳过已存在结果」逻辑。
3. **监控**：可用 `nvidia-smi`、`htop` 监控 GPU/CPU，确保各机负载均衡。
4. **结果校验**：汇总后检查 `error` 字段，对失败样本重跑。
